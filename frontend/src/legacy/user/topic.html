Method Resolution Order (MRO) & C3 Linearization

Master Python's deterministic resolution graph for multiple inheritance, dynamic delegation via super(), and how to avoid cyclic diamond dependency errors in large codebases.

1. Why Does Python Need C3 Linearization?

When a class inherits from multiple parents, an ambiguous inheritance diamond can emerge. Python 2.2 and earlier used a naive depth-first search that broke monotonicity in complex hierarchies. Starting in Python 2.3, Guido van Rossum adopted the C3 Linearization Algorithm, guaranteeing:

  • Subclasses precede their parents: If class D inherits from B, D is always checked before B.
  • Parent ordering is preserved: If declared as class D(B, C), B and its ancestry will always take precedence over C.
  • Monotonicity: A class always precedes its superclasses across all subtrees.
Architecture Note: Attempting to create an inheritance graph that violates C3 will raise a compile-time TypeError: Cannot create a consistent method resolution order (MRO).

2. Interactive Code Example & Execution Graph

class Base:
    def execute(self):
        return ["Base"]

class WorkerA(Base):
    def execute(self):
        return ["WorkerA"] + super().execute()

class WorkerB(Base):
    def execute(self):
        return ["WorkerB"] + super().execute()

class DistributedPipeline(WorkerA, WorkerB):
    def execute(self):
        return ["Pipeline"] + super().execute()

# Inspect Resolution Order:
pipeline = DistributedPipeline()
print(DistributedPipeline.__mro__)
# Resolution: (DistributedPipeline, WorkerA, WorkerB, Base, object)

print(pipeline.execute())
# Output: ['Pipeline', 'WorkerA', 'WorkerB', 'Base']

3. Common Senior Interview Pitfalls

The "Super() calls the parent" myth: Many candidates state that super() calls the parent class. In WorkerA above, super().execute() actually calls WorkerB.execute() because WorkerB is the next item in DistributedPipeline's MRO!

Interview Questions for this Topic

Conceptual Difficulty: Intermediate

Explain the difference between __new__ and __init__ in Python.

Short Answer: __new__ is the static creator method that actually instantiates and returns the object instance in memory, while __init__ is the initializer method that configures attributes on that created instance.

💡 Senior Interview Tip: Mention immutable types (like tuple or int subclassing) and thread-safe singleton design patterns as classic use-cases for overriding __new__.
Conceptual Difficulty: Intermediate

How does Python implement Encapsulation and Name Mangling for private members?

Short Answer: Python does not enforce true private variables at runtime bytecode level. Double leading underscores (e.g. __var) trigger name mangling, transforming the attribute name to _ClassName__var to prevent accidental subclass override.

💡 Senior Interview Tip: Demonstrate that you know private attributes can still be accessed via obj._ClassName__var if someone deliberately intends to.
